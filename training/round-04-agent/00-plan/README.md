## B. 기술 배우기 — 오늘은 한 개념만

### 오늘의 용어: 로그(Log)

시스템에서 발생한 사건과 오류를 시간 순으로 남긴 기록입니다. 사고 원인을 찾을 때 살펴보는 일지에 비유할 수 있습니다.

**그림으로 보기 (교육용 개념도):**

```mermaid
flowchart LR
 A["장애 현상"] --> B["로그 분석·가설"]
 B --> C["원인 확인·복구"]
```

**생각할 질문:** 오류 로그 한 줄만으로 근본 원인을 확정할 수 있나요?

**답과 이유:** 대개 어렵습니다. 다른 증거와 재현 검사로 확인해야 합니다.
### 내 말로 설명·종이 재현 (Teach-back / Dry-run)

**두 문장으로 설명하기:** 시스템 로그(Log)는 사건과 오류의 단서를 제공합니다. 로그를 읽고 원인을 가정한 뒤 재현·확인해야 근본 원인에 가까워집니다.

**종이에 흐름을 따라 그리기**
1. **입력:** 서비스 오류를 알리는 가상 로그를 읽음.
2. **처리:** 시간·프로세스·상태를 비교하여 가설 설정.
3. **예상 결과:** 재현 가능 여부와 복구 후 변화 점검.

**흔한 오해:** 로그 한 줄이 반드시 유일한 근본 원인을 뜻하지는 않습니다.
